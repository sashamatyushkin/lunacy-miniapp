## 1. Референс: что взято с lunacy.ru

Токены сняты напрямую из `:root` продакшн-CSS сайта, а не подобраны на глаз:

| Токен | Значение | Где применяется |
|---|---|---|
| `--background` | `#0e0e0e` | фон приложения, header/bottom bar Telegram |
| `--navmenu-bg` | `#161616` | нижняя навигация |
| `--middle-grey` | `#212121` | инпуты, чипы, плашки |
| `--bg-card` | `#2b2b2b` | карточки |
| `--border-card` | `#363636` | все границы |
| `--text-primary` | `#686868` | второстепенный текст |
| `--text-secondary` | `#b6b6b6` | подписи |
| `--middle-white` | `#f4f4f4` | основной текст, акцент, primary-кнопка |

- Шрифт — **Inter**, 400/500/600/700.
- `border-radius: 3px` — на сайте это доминирующее значение (20 из 33 объявлений). Интерфейс намеренно «прямоугольный».
- Заголовки — **строчными** (`популярные товары`, `категории`, `о нас`). Это главный узнаваемый приём типографики сайта, перенесён на все экраны.
- Цветовых акцентов нет: вся палитра — градации серого, акцент = белый.

Каталог перенесён реальный: 24 товара, 5 категорий (клавиатуры, мышки, наушники, коврики, рукава), цены 1 490 – 19 990 ₽.

## 2. Логика магазина

```
Telegram bot ──/start──▶ кнопка «открыть lunacy» ──▶ Mini App (fullscreen)
                                                        │
                                                   initData
                                                        ▼
                                          POST /api/auth/telegram
                                          проверка HMAC на сервере
                                                        ▼
                                              User в PostgreSQL  ──▶ JWT
```

Пользовательский сценарий:

1. **Лента** — сторис, 3D-клавиатура, блок 67, популярное, категории, «о нас».
2. **Каталог** — поиск + фильтр по категориям.
3. **Товар** — фото, цена, характеристики, «смотрите также». CTA — Telegram MainButton.
4. **Корзина** — количество, итого. Корзина живёт на сервере, а не в localStorage: пользователь открывает магазин с разных устройств.
5. **Оформление** — имя, телефон, адрес. Черновик формы сохраняется локально, чтобы не терялся при закрытии.
6. **Оплата** — сервер считает сумму по своей же корзине, создаёт заказ и запрашивает у Telegram invoice link. Клиент открывает счёт через `openInvoice`.
7. **Подтверждение** — заказ становится `PAID` **только** в вебхуке бота, после `pre_checkout_query` (сервер сверяет сумму) и `successful_payment`. Фронтенд не может объявить оплату успешной.
8. **Профиль** — заказы, статусы, реферальная ссылка.

Статусы заказа: `DRAFT → AWAITING_PAYMENT → PAID → SHIPPED → DONE`, плюс `CANCELLED`.
Если счёт не создался — заказ сохраняется в `AWAITING_PAYMENT`, и его можно оплатить повторно (`POST /api/orders/:id/pay`).

## 3. Схема данных

`User` (tgId unique, refCode unique, referredById) · `Category` · `Product` (slug unique, categoryId) · `CartItem` (unique userId+productId) · `Order` · `OrderItem` · `Payment` (orderId unique, payload unique) · `Story` · `AnalyticsEvent`.

Ключевые ограничения, которые защищают логику:
- `Payment.payload` unique → повторная доставка вебхука не проводит оплату дважды.
- `CartItem` unique по паре → «добавить ещё раз» инкрементит, а не плодит строки.
- `OrderItem` хранит `title` и `price` на момент покупки — изменение цены не переписывает историю.

Снять токены из CSS сайта, выписать каталог, определить структуру экранов.

### ✅ Шаг 5. Telegram-авторизация
Проверка HMAC initData по официальному алгоритму, TTL подписи, upsert пользователя, JWT.

### ✅ Шаг 6. Экраны и навигация
Лента, каталог, товар, корзина, оформление, заказ, профиль. BackButton / MainButton / haptics / safe area / fullscreen.

### ✅ Шаг 7. Платежи и аналитика
`createInvoiceLink`, `pre_checkout_query`, `successful_payment`, идемпотентность, повторная оплата, whitelisted-события.

### ◐ Шаг 8. Реальные ассеты
- ✅ Сторис: три присланных скриншота обрезаны (снята панель «Найти связанный контент»), кнопка play убрана inpaint-заливкой, лежат в `apps/web/public/stories/story-1..3.webp`.
- ☐ Фото товаров: положить в `apps/web/public/products/<slug>.webp` (имена = slug из сида). Пока файла нет, карточка рисует монохромный постер — интерфейс не выглядит сломанным.

### ◐ Шаг 9. Бот и деплой
- ✅ Бот `@lunacyapp_bot` подключён: токен и секреты в `.env`, вебхук привязан, кнопка меню «магазин» и команда `/start` настроены.
- ✅ `npm run up` / `npm run down` — поднимает и гасит весь стек (API → фронтенд → туннель → привязка бота), как в LIT.
- ☐ `@BotFather` → `/newapp`, short name `shop` — нужно для реферальных ссылок `t.me/<bot>/shop?startapp=…`; интерактивный диалог, руками.
- ☐ Постоянный домен вместо туннеля для прода.

### ☐ Шаг 10. Реальные платежи
Для MVP включены **Telegram Stars** (`PAYMENT_CURRENCY=XTR`) — не требуют платёжного провайдера и работают сразу.
Для рублей: получить provider token у ЮKassa через BotFather, поставить `PAYMENT_CURRENCY=RUB` и `PAYMENT_PROVIDER_TOKEN`.

### ☐ Шаг 11. Админка
Пока контент меняется через сид/БД. Когда понадобится — минимальная панель на тех же роутах: товары, заказы, статусы, сторис.

### ☐ Шаг 12. Наблюдаемость
Отправка событий в БД уже есть. Дальше: агрегирующие запросы (воронка `app_open → product_open → add_to_cart → checkout_start → payment_success`) и алерт на упавшие платежи.

## 5. Известные ограничения

- Товарных фото в репозитории нет — см. шаг 8.
- Админки нет — см. шаг 11.
- Учёт остатков — булев `inStock`, без количеств. Для MVP достаточно; при росте нужен резерв под заказ.
- Docker-compose написан и корректен, но на этой машине Docker не установлен — проверка шла на локальном PostgreSQL 16.
- Cloudflared на этой сети не пробивается (режется соединение с edge-адресами), поэтому туннель поднимается через localtunnel. Адрес `lunacyapp67.loca.lt` живёт, пока запущен процесс; после перезагрузки Mac нужен повторный `npm run up`.
